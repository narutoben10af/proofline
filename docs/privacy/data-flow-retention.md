## Deletion semantics

“Delete” means only the scopes listed in the returned receipt and verified by a test. It must not imply secure overwrite or removal from provider systems, infrastructure logs, backups, transient buffers, browser/OS caches, screenshots, or downloaded exports. TTL is a backstop; user-triggered deletion must still stop new work and handle in-flight operations.

For any deployed byte-storage path, retain non-content evidence sufficient to prove: request time, completion time, app-managed file/byte counts, directory absence, provider-sent flag, partial failures, and receipt expiry. Never retain filenames, document text, extracted values, or content-bearing provider payloads as deletion evidence.

Act 709's Retention Principle requires personal data not to be kept longer than necessary and reasonable steps to destroy or permanently delete it when no longer required. This design register does not prove that statutory outcome across infrastructure. See the [official Act 709 text](https://www.pdp.gov.my/ppdpv1/wp-content/uploads/2024/07/UNDANG-UNDANG-MALAYSIA_AKTA_PERLINDUNGAN_DATA_PERIBADI_2010_709_MALAY_AND-ENG_V2022.pdf).
